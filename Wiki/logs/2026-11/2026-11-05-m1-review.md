## Learned
- **Subagents can't message each other by name.** Notes go through the main session, which relays them by agent ID. Tell agents this up front.
- **Parallel fixers need separate files,** even within one file such as `ProjectContents.cpp`, or they conflict. When a type change forces an edit in another fixer's file, announce it and keep it to the forced lines. The only conflict that then remains is the generated `Wiki/logs/README.md`, fixed by re-running `update_indexes.py`.
- **"Reproduce first" pays off.** The `--outdate-checks` race couldn't be reproduced from the CLI, and the real fix turned out to belong in the core (PR #26). Fixers also reported items as "not reproduced" instead of changing code blind.
- **Test fixtures and fingerprints.** When the fingerprint recipe changes, recompute only the fingerprints that matched under the old build, so deliberately stale checks stay stale. Check the fixed-example hash independently (Python's `hashlib` on the exact bytes).
- **An approved spec still leaves gaps.** Most fix PRs needed a reading the spec didn't give; recording them as numbered amendments that Dakota approves by merging kept the spec the contract.
- **Use a real Qt install.** A Qt install left in a temporary folder lost files mid-session, so a fresh configure failed. Install Qt with the Qt Online Installer, as the spec says.
