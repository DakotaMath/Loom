# 001: Qt 6.11 for the UI, and Qt Core in LoomCore

> **Summary:** Loom uses Qt 6.11.1 (LGPL v3): Widgets, Gui and Test for `LoomApp` and its tests, and Qt Core alone in `LoomCore`, which gets SHA-256, Unicode normalisation, atomic writes, processes and random numbers from it without another library.

**Last verified:** 2026-11-03 · commit 7580298
**Status:** Accepted
**Decided by:** Dakota, in the design (`Specs/loom.md`, 2026-11-03) and the approved M1 spec (`Specs/m1-core.md`, 2026-11-03); this page records it for #3

## Context
The design chose C++20 with Qt 6 Widgets for the UI. `LoomCore` must have no UI code (CLAUDE.md hard rule 2), but it needs SHA-256 for fingerprints, Unicode normalisation for the paper key rule, atomic file writes, a way to run `git`, and a system random source for IDs. The standard library has none of the first four.

## Options considered
| Option | Pros | Cons |
| --- | --- | --- |
| Qt Core in `LoomCore` | One dependency already needed for the UI; `QCryptographicHash`, `QString::normalized`, `QSaveFile`, `QProcess`, `QRandomGenerator::system()` are well tested | `LoomCore` and its tests need Qt's DLLs at run time |
| Standard library plus small libraries (a SHA-256 header, utf8proc, hand-written atomic writes and process code) | `LoomCore` free of Qt | Three or more extra dependencies, each needing a decision page; process and atomic-write code is easy to get wrong on Windows |

## Decision
- **Version:** Qt 6.11.1, the same on Dakota's machine and in CI. 6.12.0 is out but is a .0 release; move up at 6.12.1.
- **Modules:** `LoomCore` and `loom` link `Qt6::Core` only. `LoomApp` links `Qt6::Widgets` (and so Gui); `LoomAppTests` adds `Qt6::Test`. Qt PDF and WebEngine come when M2 needs them.
- **Enforced:** the configure fails if anything links Gui, Widgets or WebEngine into `LoomCore`, directly or through another target (`Source/CMake/LoomCoreLinkCheck.cmake`).
- **Getting it:** on Windows, the Qt Online Installer's *MSVC 2022 64-bit* component (it works with Visual Studio 2026's compiler); in CI, `jurplel/install-qt-action@v4`.

## Why
Qt is already required for the UI, so using its Core module in `LoomCore` costs no new dependency and gives tested implementations of the hard parts. Qt Core has no UI code, so the rule that `LoomCore` stays testable on its own still holds.

**Licence:** Qt is LGPL v3 (and GPL v3), linked dynamically; compatible with Loom's GPL v3.

## Consequences
- On Windows, anything linking `LoomCore` needs Qt's `bin` folder on `PATH` to run. The CMake tests set it themselves; running `loom` or `LoomApp` by hand needs it set ([how-to](../how-to/build-on-windows.md)).
- Qt 6.11 can't be installed on Windows CI by aqtinstall's last release ([gotcha](../gotchas/ci/aqtinstall-qt-6-11-windows.md)).
